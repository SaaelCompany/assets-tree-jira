# Дерево активов для Jira Service Management 4.21.1

Плагин для Jira Service Management **4.21.1** (платформа Jira **8.21.1**, байткод **Java 8**). Экран встроен в страницу Jira. Готовых макетов нет: в списке только ваши проекты, типы объектов и активы вы создаёте сами. Чужой проект в дереве не появляется.

Данные лежат в базе Jira через Active Objects. Отдельная база не нужна. Пользователи берутся из каталога Jira, в том числе из Active Directory.

## Как это закрывает задачу

1. **Проекты не пересекаются.** Дерево, типы, поля, статусы и доступ групп принадлежат проекту. Экран активов виден тем, кто может просматривать проект, и группам из настроек этого проекта. Администратор Jira видит все. Клиент портала, у которого есть только создание заявок, экран не видит: на портале ему доступно поле «Актив проекта». Правка дерева — это отдельное право, не «Редактирование задач». Актив другого проекта для запроса возвращается как «не найден».
2. **Иерархия.** Корень — проект. Под площадкой видны типы оборудования: Усть-Лабинск, затем Ноутбук, Принтер, Монитор. Клик по филиалу открывает его как заявку Jira без статуса: панель действий, детали, описание по клику, люди и даты. Типы и отделения внутри идут строками связанных заявок, без плашек статуса. Цифры и статусы живут в пункте **Сводка**. Клик по типу открывает всё оборудование этого типа. Плюс на площадке либо добавляет площадку внутрь, либо заводит тип. Объект создаётся плюсом на типе.
3. **Статусы.** У каждого проекта свой список. Сразу есть шесть: на складе, в эксплуатации, в ремонте, в резерве, на обслуживании, списан. В настройках проекта их можно переименовать, добавить и удалить, если статус не используется. Цвет плашки выбирается из палитры: к выполнению, в работе, готово, синий, оранжевый, красный, фиолетовый, бирюзовый, серый, розовый, салатовый, коричневый.
4. **МОЛ из каталога.** В карточке выбирается пользователь Jira. Имя, почта, телефон, отдел, должность и каталог подтягиваются из профиля и атрибутов пользователя (телефон, отдел, должность — как их отдаёт AD). Пункт **Мои активы** показывает оборудование, где текущий пользователь указан ответственным: статус, проект и место в дереве.
5. **Иконки типов.** У каждого типа — цвет и иконка в стиле Jira: цветная плашка с белым знаком, как у типов запросов на портале. Набор из 32 иконок: здание, склад, отделение, офис, больница, компьютер, ноутбук, монитор, сервер, принтер, телефон, сеть, медицина, транспорт и другие. Иконка выбирается при создании типа и меняется в окне **Типы** или в настройках; она видна в дереве, в списках, в карточке и в сводке. Новые типы и правки схемы появляются на экране сразу, без перезагрузки страницы.
6. **Свои поля у типа.** Поля задаются у типа площадки и у типа оборудования: при создании площадки, в окне **Типы** и в настройках. У филиала можно держать адрес и ответственного, у ноутбука — модель, RAM и ROM, у аппарата УЗИ — модель, серийный номер и производителя. Поля бывают текстом, многострочным текстом, числом и пользователем. Обязательное поле пустым не сохраняется. В настройках открыт один раздел: статусы, типы или доступ. Поиск сужает список. Поля видны только у типа, который выбран слева.
7. **Сводка.** Пункт меню **Сводка** показывает цифры по оборудованию: сколько единиц, площадок, в ремонте, на обслуживании, без ответственного и списано. Рядом кольцо статусов, типы, площадки с наибольшим числом объектов и ответственные. Клик по цифре или строке открывает **Все активы** с этим отбором, клик по площадке открывает её. На экране **Все активы** сводки нет. Статусы и типы считаются только по оборудованию.
8. **Заявки.** На портале поле **Актив проекта** идёт по дереву: филиал, отделение, оборудование. Можно остановиться на любом уровне. Значение пишет связь заявки с активом того же проекта. На карточке заявки панель **Активы** ищет и привязывает ещё оборудование — тоже только своего проекта. Так видно, например, по какой заявке принтер списан.

## Сборка

Нужен JDK 8 и Maven 3.6+. На более новой JDK плагин соберётся, только если байткод останется 1.8: Jira 8.21 класс новее не загрузит.

```bash
export JAVA_HOME=/usr/lib/jvm/java-8-openjdk-amd64
mvn -B package
```

Готовый файл: `target/asset-tree-1.2.42.jar`.

```bash
mvn -B test
```

## Установка

Если Asset Tree уже включён, загрузите новый jar поверх: это обновление. Если в списке лежит отключённое приложение, удалите его и загрузите jar заново. Обновление поверх приложения, которое не запустилось, оставляет старую ошибку.

1. **Администрирование → Приложения → Управление приложениями → Загрузить приложение** и выберите jar.
2. Разведите роли в схемах прав, как в разделе ниже. Пункт **Активы** виден тем, кто может просматривать проект, и группам с доступом в настройках. **Настройки** — тем, кто ведёт схемы или решает доступ групп: администраторам, праву «Изменение активов», «Управление активами» и группам с правом «Схема» или «Доступ».
3. Пункт **Активы** в верхней навигации открывает меню: **Мои активы**, **Все активы**, **Сводка**, **Настройки**. Те же разделы продублированы вкладками над страницей: **Мои активы**, **Активы**, **Сводка**, **Настройки**. Вкладка **Настройки** видна тем же людям, что и пункт меню. Поиск стоит на экране **Все активы**: строка ищет по имени, ключу, описанию и полям в выбранном проекте или во всех видимых. Рядом список сортируется по полю, а правила можно сохранить как свой фильтр. В боковом меню проекта ссылка открывает активы этого проекта: `/plugins/servlet/asset-tree?project=KEY&view=all`. Сводка: `/plugins/servlet/asset-tree?view=dashboard`.
4. Для портала: **Администрирование → Задачи → Настраиваемые поля → Добавить**, тип **Актив проекта**. Повесьте поле на нужный тип запроса Service Desk и на экран. Медицине — на тип заявки портала. ИТ может не выводить его на портал и пользоваться только панелью на карточке.
5. Клиент портала остаётся в роли Service Desk Customers: создание заявок есть, просмотра проекта нет. Тогда каскад на портале работает, а экран активов не открывается.

## Роли

Чужой проект не появляется. Человек видит только те проекты, где у него есть просмотр (или он администратор Jira).

| Кто | Куда посадить в Jira | Что может в активах |
| --- | --- | --- |
| Администраторы Jira | группа `jira-administrators` | Все проекты, дерево и схемы |
| Руководители проектов | роль **Administrators** своего проекта | Дерево и схемы только этого проекта |
| Инженеры по эксплуатации, которые ведут учёт | роль проекта, например **Ведёт активы**, и в схеме прав этого проекта право **Изменение активов** | Правят дерево и схемы только этого проекта |
| Сотрудники техподдержки, мед инженеры | роль **Service Desk Team** или **Users**: просмотр и работа с заявками, без «Изменение активов» | Видят дерево своего проекта и привязывают актив к заявке. Дерево не меняют |
| Пользователи портала техподдержки | роль **Service Desk Customers** | Только поле «Актив проекта» на портале. Пункта «Активы» нет |
| Группа из настроек проекта | **Настройки → Доступ групп** этого проекта | Свой набор только этого проекта. Оборудование — это создание, удаление, комментарии и файлы одним правом. Карточка меняет название, поля, статус и МОЛ. Площадки переставляют филиалы в дереве. Схема и доступ выдаёт руководитель. Просмотр входит в любой другой набор. Пустой список не отменяет права Jira |

Право проекта **Изменение активов** лежит в схеме прав, блок проектов: **Администрирование → Задачи → Схемы прав**. Выдайте его роли, а не группе «все сотрудники». Мед инженеров добавьте только в медицинский проект, техподдержку — в проект Service Desk, эксплуатацию — в свой. Один и тот же человек в двух проектах видит два дерева и правит то, где у него есть право.

Глобальное право **Управление активами** (**Администрирование → Система → Глобальные права**) правки даёт во всех проектах, которые человек и так просматривает. Оно нужно, только если одна группа ведёт учёт сразу в нескольких проектах. В остальные проекты эту группу не добавляйте.

Язык экрана совпадает с языком пользователя Jira: русский или английский.

## Как вести дерево

1. Плюс у проекта добавляет филиал. Назовите тип площадки и сам филиал, поля — адрес и ответственный.
2. Плюс на филиале: **Тип оборудования** — Ноутбук, Принтер, Монитор или УЗИ, у каждого свои поля. Тип сразу появляется под филиалом. **Площадка внутри** — отделение или кабинет; типы переезжают под него.
3. Клик по типу показывает оборудование. Плюс на типе добавляет объект: планшет Samsung или УЗИ GE, статус «В эксплуатации», МОЛ.
4. Карточка оборудования собрана как заявка Jira: панель действий, детали, описание по клику, вложения и активность. Статус — цветная плашка, как в заявке, и меняется с неё. МОЛ меняется в блоке «Люди». Комментарий выглядит как в активности заявки. Файл, в том числе PDF, кладётся в зону вложений или выбирается через «обзор». В активности видны комментарии и история: кто создал объект, сменил статус, МОЛ, поле или файл. У площадки слева постоянная метка из точек. Тяните за неё: верхняя треть строки — перед узлом, нижняя — после, середина — внутрь.
5. В блоке задач укажите ключ заявки того же проекта, например `SD-14`.

Удаление узла с потомками спрашивает подтверждение и снимает ветку, поля и связи.

## REST

Базовый путь: `/rest/asset-tree/1.0`. Нужна сессия Jira и заголовок `X-Atlassian-Token: no-check`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/meta` | Проекты, право на запись, ключ текущего пользователя, строки интерфейса |
| GET | `/assets?projectKey=IT` | Дерево, типы и статусы проекта. `q` — до 30 совпадений |
| POST | `/assets` | Создать узел (`projectKey`, `custodianKey`, поля) |
| GET | `/assets/{id}` | Карточка |
| PUT | `/assets/{id}` | Изменить карточку и значения полей |
| POST | `/assets/{id}/move` | `{"parentId": 1, "index": 0}` |
| DELETE | `/assets/{id}?cascade=true` | Удалить узел или ветку |
| POST | `/types` | Свой тип: `label`, `projectKey`, `location`, `color`, `icon`, `showInTree`. Без `icon` площадка получает `building`, оборудование — `device` |
| PUT | `/types/{typeKey}` | Частичное обновление: `{"showInTree": false}` — не разворачивать объекты этого типа в меню; `{"icon": "printer"}` и `{"color": "#DE350B"}` — внешний вид. Незаданные поля не трогаются |
| DELETE | `/types/{typeKey}` | Удалить неиспользуемый свой тип |
| POST | `/types/{typeKey}/fields` | Поле: `label`, `kind`, `required` |
| DELETE | `/types/{typeKey}/fields/{fieldKey}` | Удалить поле |
| GET | `/projects/{key}/statuses` | Статусы проекта |
| POST | `/projects/{key}/statuses` | Добавить статус: `label`, `category` (`todo`, `progress`, `done`, `blue`, `orange`, `red`, `purple`, `teal`, `gray`, `pink`, `lime`, `brown`) |
| PUT | `/projects/{key}/statuses/{statusKey}` | Переименовать статус или сменить категорию |
| DELETE | `/projects/{key}/statuses/{statusKey}` | Удалить неиспользуемый статус. Последний остаётся |
| GET | `/projects/{key}/grants` | Группы и набор `caps`: `view`, `create`, `edit`, `move`, `remove`, `comment`, `schema`, `access`. Поле `level` — сводка `view`, `edit` или `manage` |
| POST | `/projects/{key}/grants` | Выдать группе набор: `groupName` и `caps`. Старый `level` тоже принимается |
| DELETE | `/projects/{key}/grants?group=` | Снять доступ группы |
| GET | `/groups?q=` | Поиск группы Jira, до 15 |
| GET | `/projects/{key}/report` | Отчёт проекта |
| GET | `/projects/{key}/picker` | Дерево для каскада на портале |
| GET | `/users?q=` | Поиск пользователя, от двух символов |
| GET | `/users/{userKey}/assets` | Что числится на пользователе |
| GET | `/issues/{id}/context` | Проект заявки |
| GET | `/issues/{id}/search?q=` | Поиск активов этого проекта |
| GET | `/issues/{id}/assets` | Связанные активы |
| POST | `/issues/{id}/assets` | `{"assetId": 1}` |
| POST | `/assets/{id}/issues` | `{"issueKey": "SD-14"}` |
| DELETE | `/assets/{id}/issues/{issueId}` | Снять связь |

## Предпросмотр без Jira

Рядом лежит сервер с тем же экраном и тем же REST. Это не плагин и не список ваших проектов: без Jira список пуст. В установленном плагине в списке те проекты, которые пользователь может открыть.

```bash
python3 preview/server.py
```

- [Экран активов](http://127.0.0.1:47121)
- [Панель на заявке](http://127.0.0.1:47121/issue)
- [Поле портала](http://127.0.0.1:47121/portal)

Язык берётся из `Accept-Language`: с `en` — английский, иначе русский.

## Совместимость

Собрано против API Jira 8.21.1 и Active Objects 3.5.1. Плагин не зависит от API Service Desk, поэтому встаёт и на Jira Software/Core 8.21.1 той же сборки. Для Data Center в манифесте указан статус `compatible`.
